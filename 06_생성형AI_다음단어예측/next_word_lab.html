예측해 보기

아래 빈칸에 들어갈 단어를 떠올려 보세요. 왜 그 단어가 떠올랐나요?

"나는 아침마다 ______"

사람도 "많이 들어 본 말"을 먼저 떠올립니다. 언어 모델은 이 감각을 숫자(확률)로 바꾼 것이에요.

원리: 세고, 나누고, 뽑기

가장 단순한 언어 모델은 세 단계로 움직입니다. 오늘 코드도 정확히 이 순서예요.

단계하는 일코드에서
① 세기 (학습)글에서 "나는" 바로 뒤에 어떤 단어가 몇 번 나왔는지 센다counts[key][nxt] += 1
② 나누기 (확률)횟수를 전체 합으로 나눠 확률로 만든다n / total
③ 뽑기 (생성)확률이 클수록 잘 나오는 주사위를 굴려 다음 단어를 고른다random.choices(...)

온도(Temperature)는 주사위를 기울이는 손잡이

각 횟수를 1 / 온도 만큼 거듭제곱한 다음 다시 비율로 나눕니다. 직접 계산해 봅시다. "나는" 뒤에 학교에 5번, 책을 2번이 나왔다면:

온도 1.0 → 5¹ : 2¹ = 5 : 2 → 학교에 71%, 책을 29% 온도 0.5 → 5² : 2² = 25 : 4 → 학교에 86%, 책을 14% (흔한 단어가 더 유리) 온도 2.0 → √5 : √2 = 2.24 : 1.41 → 학교에 61%, 책을 39% (차이가 줄어듦)
?온도를 0에 아주 가깝게 하면 확률은 어떻게 될까? 온도가 아주 크면?

M1온도만 바꾸기기본

TEMPERATURE를 1.0 → 0.2 → 3.0 으로 바꿔 세 번 실행 (SEED는 그대로!)

힌트
n ** (1 / TEMPERATURE)에서 온도가 작으면 지수가 커져요. 5와 2의 차이가 5⁵ : 2⁵ = 3125 : 32 처럼 벌어집니다. 그래서 온도 0.2에서는 같은 문장이 반복돼요.
M2주사위 번호(SEED) 바꾸기기본

TEMPERATURE = 1.0으로 두고 SEED만 7 → 8 → 9

힌트
확률표(①②, 학습 결과)는 그대로이고 ③ 뽑기만 달라져요. 생성형 AI도 같은 확률에서 매번 다르게 뽑기 때문에 답이 달라집니다. SEED를 고정하면 실험을 똑같이 재현할 수 있어요 — 과학 실험의 "변인 통제"!
M3문맥 길이와 베끼기심화

CONTEXT를 1 → 2 → 3. 마지막 줄의 원문 베끼기 비율과 문맥 종류 수를 기록표에서 비교

힌트
문맥이 길수록 그 문맥이 나온 곳이 거의 한 군데뿐이라, 다음 단어 후보가 1개가 돼요(확률 100%). 그러면 원문을 그대로 외워 말하게 됩니다. 진짜 언어 모델은 엄청나게 많은 글로 학습해서 긴 문맥도 "외우지 않고" 다룰 수 있어요. 이것이 데이터의 양이 중요한 이유이자, 저작권 문제가 생기는 지점이기도 합니다.
M4오류를 고쳐라: 온도 0코딩 도전

TEMPERATURE = 0 으로 실행하면 오류가 납니다. 오류 이름과 줄 번호를 읽고, 온도가 0이면 가장 많이 나온 단어를 고르도록 next_probs 함수를 고쳐 보세요.

힌트
1 / 0은 계산할 수 없어서 ZeroDivisionError가 나요. 함수 맨 앞에 다음 두 줄을 넣어 보세요.
if TEMPERATURE == 0 and c:
    best = max(c, key=c.get)
    return {best: 1.0}
M5데이터를 바꾸면 모델이 바뀐다도전

TEXT 안에 "나는 게임을 한다." 같은 문장을 여러 번 추가해 실행해 보세요. "나는" 다음 확률표가 어떻게 바뀌나요?

생각 넓히기

환각(Hallucination)

손으로 실험에서 원문에 없던 문장("나는 친구와 코딩을 한다. 축구는 재미있다." 같은)이 나왔나요? 말은 자연스럽지만 사실인지는 확인하지 않습니다. AI가 그럴듯한 거짓말을 하는 이유와 연결해 보세요.

진짜 LLM과 무엇이 다를까?

오늘 모델은 단어 횟수를 표로 외웁니다. 진짜 LLM은 수천억 개의 가중치(1차시의 W!)로 확률을 계산해요. 그래도 "다음 단어 확률 → 뽑기"라는 마지막 단계는 같습니다.

누구의 글일까?

문맥을 길게 하면 원문을 그대로 베꼈어요. 많은 사람의 글을 학습한 AI가 만든 글의 주인은 누구일까요?
